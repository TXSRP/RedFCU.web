Privacy

Privacy

This website is a set of static pages. It does not track you and it does not ask you for personal information.

What this site does not do

  • No analytics, advertising, or tracking scripts.
  • No visitor accounts and no sign-in service. The hidden staff panel described below compares a typed name with a public list of project accounts on this site, and never contacts Discord.
  • No forms that send information anywhere. The Verified Creator and Verified Community application forms build downloadable JSON files in your browser. The staff panel's fields stay in your browser.
  • No cookies.
  • No third-party fonts, embeds, or external scripts.
  • No backend, database, or server-side code.

The pages load their stylesheet, a few small scripts, the favicon, and two small data files from this website. No other network requests are made by the site itself.

Theme preference stored in your browser

If you use the light/dark toggle, your choice is saved in your browser's local storage under the key redfcu-theme, with the value light or dark. It stays on your device and is not sent anywhere.

The site reads that value when a page loads so your chosen theme is applied straight away. Clearing site data, or browsing in a private window that clears storage, removes it. Nothing else is stored.

If your browser blocks or limits local storage, the site does not break. It falls back to your operating system's color preference, and the toggle still changes the theme for the current page.

What else can be stored in your browser

Two more keys exist, and only staff write them. Both stay on the device:

  • redfcu-staff — written only if a staff member unlocks the hidden staff panel. It holds the account name and an expiry time, so the panel does not ask again on that browser for twelve hours.
  • redfcu-release-draft — written only if a staff member previews an edited release. It holds the version, date, package name, and size being previewed.

These are not cookies, and no other site or service reads them. Clearing site data removes them. If storage is blocked, the panel still works but forgets the preview when the page reloads.

Verified Creator and Verified Community applications

The Verified Creator and Verified Community application forms do not submit to a server. Each one checks your answers in your browser and creates a JSON file that you download. The file contains what you typed, the date, and the confirmations you selected. It stays on your device until you choose to send it to a staff member.

This website does not receive, store, or publish the file. If you send it through Discord or another service, that service's privacy terms cover the message and any attachment. A staff member reads the file in their browser; the site keeps no copy and has no database of applications.

If an application is accepted, staff prepare a verification ID and a message, and send you the Red FCU badge image for that program. The badge artwork is made by Red FCU; the review tool does not generate it. Neither program publishes an application or a public directory entry on this website.

If a verification is later withdrawn, staff generate a withdrawal message in the same browser tool. The site does not store the message or a revocation list. A badge that has already been sent cannot be deleted; withdrawal ends the permission to use it.

Staff introductions

When the owner hires a staff account, the hidden panel creates an introduction in the browser. It uses the Discord username, an optional first or public name, and optional pronouns. It does not ask for or include physical addresses, phone numbers, IP addresses, Social Security numbers, drivers license or state ID numbers, last names, or middle names.

Rank, age, and favorites are always written as Not Disclosed. Red FCU staff are not allowed to display rank, age, or favorites to servers that are not verified with Red FCU. The introduction is generated only in the owner's browser; this site does not send, publish, or store it. The owner copies it and sends it to the person.

The hidden staff panel

Every page contains a hidden panel for the project's own staff, opened with Left Alt + F2. It exists so the release details shown across the site can be edited in one place, so admin and owner accounts can review Verified Creator and Verified Community applications and withdraw a verification, and so the owner can hire staff and generate their introductions. It is documented in the project's README.

Signing in means typing a Discord username or user ID that appears in assets/data/staff.json, a public file on this site. That file holds only public profile details: a username, a display name, a user ID, a role label, and optionally a PBKDF2 value derived from a staff code. It holds no passwords, tokens, or email addresses.

This is not a Discord sign-in and it is not authentication. The site has no backend and never contacts Discord, so the panel cannot prove who someone is, and the account list is readable by anyone who opens the file. It is a convenience lock, not a security boundary: it contains no private information, and anything it changes affects only the browser it is used in. A release change reaches visitors only when assets/data/release.json is committed to the repository.

The review tool reads an application file only in the staff member's browser. It does not upload the file, and the site stores no application. If staff accept, the tool prepares a message and offers the official badge image for download. If staff withdraw a verification, the tool prepares a message and keeps no record. The staff member sends everything to the applicant themselves. Nothing is published or sent automatically.

External links and downloads

Links marked as external lead to other services: GitHub, which hosts the Red FCU package and its releases; the Red FCU Discord server; and Ollama's website and documentation. Nothing is sent to any of them until you click a link.

Downloading the plugin takes you to GitHub, so GitHub's privacy statement covers that download and any account you use there. Discord needs an account to join a server, and its own terms apply. This site is not told when you visit any of them, and it receives no data from them.

Hosting and technical request data

This website has no backend of its own. When it is served by a hosting provider such as GitHub Pages, that provider processes standard technical request data as part of delivering the files, such as the requested page, browser type, and IP address. That processing is controlled by the host, not by this website.

This page does not describe any hosting provider's practices in detail and is not a substitute for their privacy statement.

What this page does not cover

This page describes the website only. It does not describe data handling inside the Red FCU Unity plugin or inside Ollama, and neither has been reviewed for this page.

The project's README describes Red FCU as processing project files through the locally running Ollama instance rather than through a Red FCU server, and as requiring no cloud API key. That is the project's own description, repeated here without independent verification. For the details, use the project's documentation and Ollama's.
